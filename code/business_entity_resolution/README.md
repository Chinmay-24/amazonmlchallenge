# Business Entity Resolution System

## Overview

This is a complete entity resolution system for the Amazon ML Challenge. The system matches business entities across three independent data sources using a multi-stage pipeline:

1. **Blocking/Candidate Generation** - Multi-strategy blocking to reduce search space
2. **Feature Engineering** - Comprehensive string similarity and pattern-based features
3. **ML Matching** - LightGBM classifier optimized for F_0.5 score
4. **Output Generation** - TSV-formatted submission files

## System Architecture

```
┌─────────────────┐
│  Data Loading   │ → Load and preprocess TSV files
└────────┬────────┘
         ↓
┌─────────────────┐
│    Blocking     │ → Generate candidate pairs (4 strategies)
└────────┬────────┘   - Country blocking
         ↓             - Token blocking (name + address)
┌─────────────────┐   - N-gram blocking
│Feature Engineer │   - Phonetic blocking
└────────┬────────┘
         ↓
┌─────────────────┐
│  ML Classifier  │ → LightGBM model
└────────┬────────┘   - F_0.5 optimization
         ↓             - Threshold tuning
┌─────────────────┐
│ Output Generator│ → Generate TSV files
└─────────────────┘   - candidate_pairs.tsv
                      - matching_results.tsv
```

## Output Files

The system generates two TSV files in the `output/` directory:

### 1. candidate_pairs.tsv

Contains all candidate pairs generated by the blocking stage:

```
source1_entity_id	candidate_entity_ids
S1-00001	S2-00047,S2-00193,S3-00812
S1-00002	S3-00004
S1-00003	
```

### 2. matching_results.tsv

Contains final entity matches predicted by the model:

```
source1_entity_id	matched_entity_ids
S1-00001	S2-00047,S3-00812
S1-00002	S3-00004
S1-00003	
```

**Format Requirements**:
- Tab-separated values
- Comma-separated ID lists (no spaces)
- Empty string for entities with no matches
- No duplicate IDs within lists

## Algorithm Details

### 1. Blocking Strategy

**Multi-strategy blocking** to generate high-recall candidate sets:

**Strategy 1: Country Blocking**
- Exact match on country field
- Ensures no cross-country false matches

**Strategy 2: Token Blocking**
- Inverted index on tokens from business name
- Inverted index on tokens from address
- Finds entities sharing at least one significant token
- Filters tokens < 3 characters and common stop words

**Strategy 3: N-gram Blocking**
- Character trigrams from business name
- Captures misspellings and abbreviations
- Robust to word order changes

**Strategy 4: Phonetic Blocking**
- Simple phonetic encoding (similar to Soundex)
- Removes vowels, deduplicates consonants
- Handles pronunciation-based variations

**Result**: Union of all strategies for maximum recall

### 2. Feature Engineering

**35+ features** across multiple categories:

**String Similarity Features (Name & Address)**:
- Jaccard similarity (token-based)
- Normalized Levenshtein distance
- Jaro-Winkler similarity
- Character n-gram similarity (bigrams, trigrams)
- Longest common substring ratio
- Token overlap ratios

**Business Name Specific**:
- Legal suffix extraction and matching (Ltd, Corp, Inc, etc.)
- Similarity without legal suffixes
- Name length features

**Address Specific**:
- Numeric component overlap (house numbers, ZIP codes)
- Token-weighted similarity
- Address length features

**Combined Features**:
- Average name + address similarity
- Max similarity across metrics
- Country exact match

### 3. ML Model

**LightGBM Gradient Boosting Classifier**

**Model Parameters**:
```python
{
    'objective': 'binary',
    'boosting_type': 'gbdt',
    'num_leaves': 31,
    'learning_rate': 0.05,
    'max_depth': 7,
    'feature_fraction': 0.8,
    'bagging_fraction': 0.8,
    'min_child_samples': 20,
    'reg_alpha': 0.1,
    'reg_lambda': 0.1
}
```

**Training Process**:
1. 80/20 train/validation split
2. Early stopping (50 rounds)
3. Threshold optimization for F_0.5
4. Feature importance analysis

**Why LightGBM?**:
- Fast training and inference
- Handles categorical and numeric features
- Built-in regularization
- Excellent for entity matching tasks
- MIT license compliant

### 4. Threshold Optimization

Optimizes classification threshold for **F_0.5 score** (precision-weighted):

```
F_0.5 = (1.25 × Precision × Recall) / (0.25 × Precision + Recall)
```

**Process**:
1. Grid search over thresholds [0.1, 0.9]
2. Evaluate F_0.5 on validation set
3. Select threshold with best F_0.5
4. Typical optimal threshold: 0.6-0.8 (higher than 0.5 due to precision weighting)

## Performance Considerations

### Blocking Efficiency

The blocking stage is critical for scalability:

- **Reduction ratio**: Typically 100-1000x reduction in comparison space
- **Recall ceiling**: ~95-98% of true matches captured
- **Average candidates per S1**: Aim for < 100 candidates

### Training Time

On typical hardware:
- **Training**: 5-15 minutes (depends on dataset size)
- **Inference**: 2-5 minutes
- **Feature generation**: Most time-intensive step

### Memory Usage

- Peak memory: ~2-4 GB for typical dataset sizes
- Feature matrix is the largest object in memory

## Troubleshooting

### Issue: "Module not found" errors

**Solution**: Install dependencies
```bash
pip install -r requirements.txt
```

### Issue: "File not found" errors

**Solution**: Check data directory structure matches the expected format

### Issue: Validation fails

**Solution**: 
1. Check TSV format (tab-separated, not comma)
2. Verify all Source 1 entities are present
3. Ensure no duplicate IDs in lists

### Issue: Low F_0.5 score

**Solution**:
1. Increase blocking strategies for better recall
2. Add more features
3. Tune model hyperparameters
4. Optimize threshold on validation set

### Issue: Too many candidates per entity

**Solution**:
1. Make blocking more selective (increase min_token_length)
2. Add filtering after blocking
3. Reduce n-gram size

## Model Tuning Guide

### Improving Recall

1. **Blocking**: Add more blocking strategies or make them less restrictive
2. **Threshold**: Lower classification threshold
3. **Model**: Reduce regularization (lower reg_alpha, reg_lambda)

### Improving Precision

1. **Features**: Add more discriminative features
2. **Threshold**: Raise classification threshold
3. **Model**: Increase regularization or max_depth
4. **Training data**: Add more hard negatives

### Improving F_0.5

1. **Optimize threshold** specifically for F_0.5 (not F1)
2. **Focus on precision** (weighted 2x in F_0.5)
3. **Balance** between recall and precision
